## 培养宗旨
{: #guide-section-1 }

本实验室研究生培养的目标，不是简单完成课程、实验和论文，而是培养能够：

1.  独立提出科学问题

2.  判断一个科学问题是否值得研究

3.  设计可靠的研究方案

4.  独立完成实验或计算分析

5.  对科研数据进行批判性解释

6.  独立解决科研过程中遇到的问题

7.  形成完整的论文和科研成果

8.  有能力向同行清晰表达科研思想

9.  能够指导低年级学生

10. 最终成长为能够独立开展科研工作的研究者

本实验室倡导的培养目标为：**从“完成导师安排的任务”成长为“能够独立决定做什么、为什么做、如何做以及什么时候停止做”。**

## 培养理念
{: #guide-section-2 }

研究生培养的目标不是把人“用满”，**而是把人“养成”**：在真实科研中逐步形成独立的科学判断、可靠的研究方法与稳定的推进能力。既重视产出，也重视品格和精神。

我们强调四件事：

1.  **以科学问题为中心**  
    > 研究不是任务清单，而是对问题的持续思考与深入追问。把时间用在“把问题想清楚、把证据链建起来”上，而不是用实验数量替代科学判断。

2.  **以项目推进为牵引**  
    > 培养必须落在项目中，能力体现在推进上。我们认可投入与工作量，但更看重“有效推进”：每一阶段的努力，都应让项目更接近回答问题——要么获得可靠证据支撑结论，要么明确证据不足并及时调整路径。

3.  **以独立性为成长路径**  
    > 独立性不是放任不管，而是逐步授权与能力升级：从“在指导下完成”，到“能独立推进”，再到“能带动他人推进”。训练过程中允许试错，但必须学会定位问题、查找证据、提出方案并复盘，把错误转化为下一次更快、更稳的推进。

4.  **以品格与科研伦理为底线**  
    > 我们要求学生诚实、可靠、守信、团结：尊重事实与数据，如实记录实验与分析过程，确保可追溯、可复现；尊重合作者与共同体，遵守署名与贡献原则；在资源使用、实验安全与对待他人方面保持克制与责任感。真正的学术产出应当经得起复核，也经得起品格的检验。

## 适用范围
{: #guide-section-3 }

- **适用对象：** 本实验室全体研究生及参与研究生培养的博士后、高年级研究生、科研助理等

- **研究方向：** 植物基因组学、遗传学及相关交叉领域

- **实施原则：** 标准化、分层培养、项目驱动、能力导向、持续反馈、逐步授权

## 1 目标与共同原则
{: #chapter_1 }

### 培养什么样的人
{: #guide-section-7 }

实验室以植物基因组与遗传调控为基础，围绕作物的变异、遗传与调控问题开展研究，也开展相关植物体系和方法研究。不同方向应共同服务于清楚的科学问题。

成员应逐步做到：理解课题的重要性，说明要解决的问题，根据数据和假设选择方法，区分观察结果、解释与推测，发现问题后提出可讨论的方案，并让他人能够理解和重建工作。不同阶段承担的任务范围有所不同。

### 如何开展研究
{: #guide-section-8 }

1．从科学问题开始。开展新分析前，说明它回答什么问题、可能得到什么结果，以及如何解释这些结果。探索性分析也应说明希望澄清的问题。

2．用证据讨论。意见不同可以提出反例、质量检查或补充分析。导师和资深成员的判断同样需要依据。

3．如实保留工作记录。阴性结果、失败尝试和方法限制都应如实报告；隐瞒异常或只选择有利结果会妨碍研究判断。

4．主动提出方案，解释理由，并承担约定的后续工作。初期可在导师示范下完成，熟练后逐步扩大自主决定的范围。

5．明确任务的完成标准。论文、学位和重要成果需要长期推进，日常任务应拆成可检查的小步骤。

6．尊重合作和个人边界。按约定提供帮助，承认贡献。

### 怎样逐步获得自主范围
{: #guide-section-9 }

先由导师示范，再由学生说明拟采用的方法。学生在小数据上完成分析并解释结果，经复核后承担更完整的任务。能够稳定处理数据输入、质量检查和结果解释的成员，可独立决定已确认范围内的技术细节。改变研究问题、重要样本范围或核心结论时，需要与PI讨论。

### 怎样判断培养是否进步
{: #guide-section-10 }

重点观察成员能否更清楚地说明问题、解释方法、排查异常和安排下一步。项目暂未获得预期结果时，个人能力仍可能提高；发表数量和程序运行次数不能单独代表科研能力。

参考思路：Humphries研究原则、Coaker双方培养责任、Poldrack分析与培养指南。

## 2 角色与责任
{: #chapter_2 }

| **角色** | **应承担的责任** | **怎样落实** |
| --- | --- | --- |
| PI | 研究方向与关键设计；培养目标；资源协调；重要反馈 | 共同确认项目范围和完成标准；记录导师行动事项 |
| 项目负责人 | 掌握科学问题、证据、当前任务和待决定事项 | 维护项目首页；提前说明阻碍；按约定交付 |
| 项目参与者 | 负责约定模块；如实记录；与其他成员衔接 | 明确输入、输出与依赖；交付材料并记录贡献 |
| 方法或资源联系人 | 维护某一方法说明或资源入口 | 提供使用说明和已知限制；科研判断交PI确认 |
| 轮值事务成员 | 组会排程；文档入口与公共事务提醒 | 每学期轮换；记录安排；不承担学生考核 |
| 检查者 | 复核约定图表、代码或记录，并提出问题 | 明确检查范围并记录结果；复核结论仅适用于已检查范围 |

### 导师应提供的支持
{: #guide-section-12 }

PI与学生共同确定近期任务，说明关键判断和可接受的完成标准。默认每两周至少进行一次个人进度讨论；入组初期或遇到阻碍时增加短讨论。出差或集中事务影响反馈时，PI提前说明替代安排。

学生提交明确问题后，PI默认在3个工作日内确认反馈方式或讨论时间。较长的方案、代码或论文需约定反馈范围和日期；普通小材料以一周内反馈为起点，完整论文另行预约。等待关键决定期间，学生应记录依赖事项，并推进不受影响的任务。

### 学生应承担的责任
{: #guide-section-13 }

学生应参加约定讨论并提前准备，及时确认不清楚的任务，维护研究记录和材料位置，说明未按计划完成的原因，并与合作者确认输入、输出和时间。不得把尚未理解的教程或AI输出当作已经掌握的方法。

### 合作责任如何确认
{: #guide-section-14 }

项目启动时写明各自负责的部分、需要他人提供的材料，以及关键结果的复核人。学生可以提出技术意见和有依据的新想法；PI帮助判断可行性，并提供适当的小规模试验机会。新增任务、项目转交或重要分工变化应记录在项目首页。

尚无成熟方向负责人时，由PI承担科研指导。可设置轮值方法联系人，帮助解决已熟悉的具体问题。

参考思路：Coaker Mentoring Compact、SEM双方行动事项、Roberts项目负责人职责。

## 3 日常秩序与沟通
{: #chapter_3 }

### 规律工作与共同协作时间
{: #guide-section-16 }

建议共同科研时段为工作日09:00至17:30，用于交流与共同工作，不等同于每天的总工作时长。课程、假期、差旅和已约定的远程工作按实际安排执行。

成员建立规律的学习科研节奏，遵守约定的讨论和交付时间。不以工作时长代替研究判断。

### 请假和临时事由
{: #guide-section-17 }

请假时提前告知PI时间、原因、可能受影响的任务及替代安排。临时情况先简短说明，后续补充；学校要求的请假手续另行办理。特殊个人情况可私下与PI讨论。

### 每日与每周要做什么
{: #guide-section-18 }

每天开始时确定一个主要任务，结束时更新研究记录。每周五17:00前更新周报，说明本周进展、当前阻碍、下周主要任务及需要的帮助或决定；遇到假期可调整。暂时没有新结果时，如实说明尝试、记录和待解决的问题。

### 怎样求助
{: #guide-section-19 }

先查阅实验室已有手册与日志，再结合文献和资料进行排查。投入数天仍无明显进展时应求助，初学者可更早提出。求助时说明目标、输入、错误信息、已做尝试和需要的帮助。样本信息、数据损坏、权限或共享平台等问题，发现后及时通知相关负责人。

### 沟通与分歧
{: #guide-section-20 }

即时消息用于提醒和简短沟通；任务决定和方法调整应写入项目记录。讨论与批评应针对具体证据和做法，尊重成员本人。

连续未按约定反馈时，PI先了解课程、技能、任务设计及个人困难，确认事实后制定两周改进安排。复核以约定行为和工作证据为依据；进一步处理按学校规定进行。

## 4 入组与初期训练
{: #chapter_4 }

### 入组前与首日
{: #guide-section-22 }

PI提前确定一个规模可控的训练任务和资料入口。首日介绍共同规则、工作空间、联络方式、账号权限及必要的安全培训，确认课程和近期可投入时间。新生逐项确认上述事项；资源缺失时直接标明并询问联系人。

### 第一周先把工作环境用起来
{: #guide-section-23 }

1．建立个人和项目文件位置；验证计算账号、存储权限、文献获取与沟通入口。

2．完成一次小型数据读入、检查、绘图和保存；说明输入是什么、输出保存在哪里。

3．读一篇与研究方向相关的论文，写出问题、证据和一个不清楚之处。

4．在导师或联系人带领下提交一个小型计算任务，找到日志并确认资源使用方式。

5．与PI讨论训练任务的步骤、完成标准和第一次反馈时间。

### 第一个完整分析任务
{: #guide-section-24 }

默认以4至6周为一个可调整的训练周期。优先使用公开或已整理的小数据，完成数据说明、质量检查、分析、结果图、图注和方法记录。可选择小型Bulk RNA-seq任务或已确认的变异数据，各方向也可选择其他合适任务。

Linux、R、统计和版本记录的学习应结合实际任务开展。第一次结果讨论可以在任务尚未全部完成时进行，但学生必须能够说明已完成的步骤。

### 怎样确认学会了
{: #guide-section-25 }

复核时，检查学生能否说明数据与参数、指出一项质量问题、解释一张图，并在更换小数据或参数后判断结果。可选一个常见错误，要求学生说明排查思路。教程运行成功后，还需解释与验证；未掌握时缩小任务、重复关键练习，并约定新的复核日期。

### 首月讨论安排
{: #guide-section-26 }

入组最初两至三周，默认每周进行一次约20分钟的短反馈，之后转为每两周个人讨论。共性技术问题集中示范；训练任务完成后，进入真实课题的一个小模块。

参考思路：DIB完整入门项目、Roberts分阶段入组、Lowe-Power初期指导。

## 5 阶段培养与能力评价
{: #chapter_5 }

### 入组初期前六个月的月度训练
{: #guide-section-28 }

下表为计划时间点。已有基础者可提前，课程密集或需要补基础时可顺延。每月聚焦一项重点能力，用实际材料复核，并记录下一步。

| **时间** | **主要学习任务** | **可复核材料** | **导师反馈重点** |
| --- | --- | --- | --- |
| 第1月 | Linux和R基础；数据与文件管理；基本统计概念 | 小数据读入；质控或描述图；运行日志与研究记录 | 理解输入与输出；能定位和找回结果 |
| 第2月 | 完成一项小型完整训练任务，理解各步骤 | 流程说明；主要结果图、图注与脚本 | 步骤选择是否合理；数据与图是否一致；能否解释结果 |
| 第3月 | 复现一项课题相关论文中可实现的小结果 | 复现与原结果对照；方法与参数；差异排查记录 | 理解原文方法；解释差异；明确已复现的结果 |
| 第4月 | 集中阅读领域文献，梳理背景、研究进展、问题与空白 | 领域研究梳理；代表性文献；研究空白及依据 | 研究脉络是否清楚；空白是否有依据；切入点是否明确 |
| 第5月 | 完成个人课题的初步设计，开展小规模试验 | 初步方案；试验结果与质控；方案调整建议 | 问题是否具体；设计是否可行；能否扩大研究 |
| 第6月 | 分解课题，初步开展研究工作 | 模块与依赖关系表；近期计划；首轮结果、脚本与记录 | 模块与顺序是否合理；任务是否明确；哪些工作可独立完成 |

### 能力评价使用六个问题
{: #guide-section-29 }

从六个方面评价能力：说明科学问题、理解数据、解释方法、检查质量与排错、解释证据、安排与交付任务。每项记录为“需示范”“讨论后可完成”或“可独立完成已确认范围”，并附一个实际例子。

每月用约10至15分钟回顾当前材料，默认无需另做汇报PPT。对尚未掌握的能力，确定一个小练习和复核日期。培养记录供本人和导师查看。

### 六个月以后的共同路径
{: #guide-section-30 }

| **阶段** | **逐步承担的工作** | **扩大自主范围的证据** |
| --- | --- | --- |
| 6至12个月 | 稳定完成课题模块，理解方法并掌握相关文献背景 | 能解释主要选择、排查常见问题并按标准交付 |
| 12至24个月 | 推进研究主线，复核重要结果，学习结果组织与写作 | 图与结论对应；说明限制；关键结果可重建 |
| 24个月以后 | 组织完整研究、论文或学位成果，完成合作与交接 | 材料完整；结论范围恰当；他人能接续工作 |

### 硕士阶段的完成目标
{: #guide-section-31 }

按通常3年培养周期规划：前6个月打基础；6至18个月完成稳定模块并形成自己的研究范围；18至30个月组织主要结果和写作；最后阶段完成学位工作、必要补充与交接。具体开题、中期和答辩时间按学校安排。

硕士阶段的基本完成目标是：在导师帮助下完成范围明确的研究，说明背景与问题，理解所用方法，完成质量可靠的分析，解释结果与限制，并整理学位论文和可交接材料。

### 博士阶段增加的要求
{: #guide-section-32 }

博士应逐步具备独立推进研究的能力：提出有价值的问题，设计能够区分不同解释的研究，理解方法的适用条件，处理关键不确定性，并形成可说明的原创贡献。在已掌握的范围内帮助他人，同时保证本人研究的推进。

| **能力维度** | **具体要求** |
| --- | --- |
| 理解问题 | 系统理解领域背景；理解项目的核心问题；找到已有研究的不足或空白；解释研究为何需要开展。 |
| 设计研究 | 针对明确问题设计方案；将目标拆解为任务；制定里程碑；选择合适的实验或分析方法；识别关键风险并准备备选方案。 |
| 独立推进 | 独立完成主要实验或分析及数据质控；初步判断结果；根据结果调整下一步；管理项目进度。 |
| 科研判断 | 判断结果是否可靠、还需什么证据、是否需要重复、结果意味着什么，以及下一步应做什么。 |
| 科研表达 | 设计结果图并组织图序；形成研究主线和证据框架；撰写研究总结；完成论文主体框架；根据反馈修改研究方案。 |

硕士若达到表中要求，通常已表现出较好的科研独立性，能够围绕明确问题完成较完整的研究。博士应将独立设计、推进和调整科研项目作为主要训练目标。

博士后期进一步培养主导项目、指导他人和独立思考的能力。学生应能规划并推进完整项目，识别瓶颈并调整策略；在适当范围指导低年级成员，将方法和经验整理为SOP和实验室知识库；逐步形成自己的研究兴趣，提出新问题并设计后续研究。导师重点参与关键科学问题讨论、重要节点检查和重大瓶颈解决，支持学生未来独立开展科研。

### 每半年讨论一次个人发展
{: #guide-section-33 }

每半年讨论研究兴趣、已掌握能力、指导方式、学位进度与职业准备，修订下一阶段目标。转方向、项目长期无进展或资源条件明显变化时，提前回顾。讨论以实际研究材料和任务为依据。

课题状态与个人能力分别记录。可靠的阴性结果可以体现方法和判断能力的进步；结果较多但缺少解释时，仍需加强训练。

## 6 文献学习与科学汇报
{: #chapter_6 }

### 文献怎么读
{: #guide-section-35 }

每周通读3至8篇领域相关文献，其中至少精读1篇与课题直接相关的论文。方法基础文献和近期研究都要阅读。先识别问题与结论，再检查关键图和方法条件，最后说明与自己课题的关系。精读记录使用附录A3。

1．说明研究背景、意义和作者要解决的问题，理解已有工作的不足。

2．找出支撑主要结论的证据，理解样本、对照和分析逻辑。

3．检查方法是否适合数据，有哪些假设、替代解释和局限。

4．确定可以借鉴的内容，以及迁移到自己研究时需要满足的前提。

5．阅读前写一个问题，读完后说明是否得到回答。

### 周报与组内正式汇报
{: #guide-section-36 }

周报帮助导师了解每个人的进展和阻碍；组内正式汇报围绕一个研究问题，帮助全组检查方法、讨论证据并确定下一步。两者共用研究记录和结果图，按各自目的组织内容。周报模板见附录A4，正式汇报及反馈记录模板见附录A5。

#### 用途与内容的区别
{: #guide-section-37 }

| **项目** | **周报** | **组内正式汇报** |
| --- | --- | --- |
| 主要目的 | 查看进展，尽早发现阻碍，安排下一步 | 讨论科学问题、方法和证据，训练研究表达 |
| 覆盖时间 | 本周及下周 | 从上次正式汇报以来的相关工作 |
| 提交方式 | 每人每周更新项目记录，导师在线查看 | 全组每周安排一名主汇报者，按名单轮换 |
| 材料形式 | 约200至300字，证据附链接，通常用10至15分钟整理 | 图文报告或PPT，按科学问题组织 |
| 内容重点 | 取得的证据、当前阻碍、下一步、需要的帮助 | 为什么研究、怎样研究、证据支持什么、还需验证什么 |
| 结果要求 | 进展必须有记录；学习、排错、阴性结果均可作为证据 | 选择能支撑判断的关键图，解释质量、限制和替代原因 |
| 反馈重点 | 任务是否清楚，阻碍怎样处理，谁需作出决定 | 问题是否有价值，方法是否合适，结论是否有依据 |
| 形成的记录 | 项目状态和近期任务 | 科学判断、方案调整及学生和导师双方的行动事项 |

#### 提交与反馈安排
{: #guide-section-38 }

周报默认每周五17:00前更新。导师在下一个工作日浏览状态，对需要决定的问题在3个工作日内回复或约定讨论时间。可能影响数据可靠性或关键任务的阻碍应及时提出。上述时限可在试行后调整。

正式汇报提前24小时共享材料，默认报告20至25分钟、讨论20至25分钟。会后1个工作日内记录决定、负责人、日期和完成标准；下次讨论先检查这些事项。首次汇报适当增加背景，后续重点说明新证据和上次反馈的处理情况。

### 正式汇报的组织顺序
{: #guide-section-39 }

依次说明课题的重要性、本次要解决的问题、数据与方法、结果支持的判断、当前限制，以及下一步验证或推进安排。每组图表都应说明它回答什么问题。关键结果说明和会后反馈的填写方式见附录A5。

正式汇报可使用Word或其他图文材料。先说明当前问题，再依次展示结果图、图注、自己的解释、限制和下一步。复杂图表可使用PPT，每页围绕一个科学判断组织。已有图表与说明可继续用于论文材料。

每张图都应说明样本或分析单位、数据来源、方法及必要的统计信息，标题尽量表达该图支持的判断。未完成结果和失败尝试可以展示，同时说明当前能判断到什么程度。

## 7 课题设计与项目推进
{: #chapter_7 }

### 启动时建立项目首页
{: #guide-section-41 }

每项课题有唯一编号、负责人、主要参与者和记录位置。项目启动时使用附录A1，说明科学问题、现有证据、数据来源、近期目标、依赖条件、主要风险和需要导师决定的事项。首页保持简短，分析细节链接到研究记录。

### 科学问题怎样确认
{: #guide-section-42 }

区分需要描述的现象、需要比较的关系和需要检验的机制。提出至少一个替代解释，并说明当前数据能够回答到什么程度。关联结果与机制结论所需证据不同；数据不足时，应调整问题范围。

### 任务怎样拆解
{: #guide-section-43 }

1．列出到近期目标所需的关键步骤，检查样本、参考文件和计算条件是否具备。

2．将步骤分成通常一至两周可检查的任务；长时间计算单独说明预计资源和监测办法。

3．每项任务写明负责人、依赖条件、约定日期和完成标准。完成标准应对应可检查的材料或判断。

4．先用小数据验证关键方法，再扩大规模。重要条件变化时记录原因和受影响结果。

5．每次讨论结束时确定必要的下一步，避免为同一成员同时安排多个主任务。

### 示例任务
{: #guide-section-44 }

含糊写法是“继续做群体分析”。可改为“完成样本信息核对与质控，列出保留和排除样本及依据，说明这些选择对后续比较的影响；提交图、检查表和生成脚本”。具体阈值由数据和设计决定。

### 课题中的决定由谁作出
{: #guide-section-45 }

成员可独立执行已确认的方法和参数范围，并提出新的技术选择。改变核心问题、关键样本、分析单位、重要数据使用范围或大规模计算计划前，应与PI讨论。保存方法选择和调整理由，便于后续解释。

### 暂停或停止一项工作
{: #guide-section-46 }

数据不足、方法假设不成立、资源无法获得或问题价值发生变化时，可缩小、暂停或停止工作。PI与负责人共同记录已知事实、停止原因、保留材料及可能的重启条件。未获得预期结果，不自动构成停止或追责的理由。

参考思路：Roberts Project Management、Humphries研究假设、Poldrack早期小规模分析。

## 8 项目状态与及时反馈
{: #chapter_8 }

### 项目状态怎样标记
{: #guide-section-48 }

| **状态** | **具体含义** | **应采取的行动** |
| --- | --- | --- |
| 推进正常 | 下一步清楚；输入和资源具备；近期任务按约定推进 | 继续执行，记录证据和下一步 |
| 需要支持 | 方法或关键决定未定，或预计关键任务延期超过一周 | 写清已做尝试和可选方案，约定短讨论及处理日期 |
| 需要及时处理 | 结论可靠性或数据完整性出现问题，关键节点严重受阻 | 及时联系PI；暂停受影响的计算或结论使用；保存现场材料 |
| 暂停或结束 | 范围调整、暂无可行条件，或已有明确停止决定 | 记录原因，保留结果及重启或交接条件 |

项目状态说明课题需要的支持，不用于学生排名。缺少可核验记录时先了解原因；阴性结果、排错和文献学习记录都可以构成工作证据。

### 每周更新四项内容
{: #guide-section-49 }

每周更新四项内容：本周证据及材料位置、当前阻碍与已做尝试、下周优先任务和完成标准、需要的帮助或决定。直接写在项目首页，正文约200至300字，复杂材料用链接补充。模板见附录A4。

### 导师怎样掌握全组状态
{: #guide-section-50 }

PI每周查看项目概览，优先处理“需要支持”和“需要及时处理”的课题，并确认待决定事项是否已回复。每月结合现有讨论，回顾项目范围、关键证据和后续风险。需要训练的个人能力另记在培养记录中。

项目概览可使用共享文档，每项项目占一行，记录问题简称、负责人、状态、最新证据、下一步、需要PI决定的事项和复核日期。初期沿用已有工具，迁移软件时不新增重复填报。

### 延期怎样处理
{: #guide-section-51 }

预计延期时，负责人说明原因、影响和新的安排建议。等待数据或导师决定时明确依赖事项。连续两次未完成约定任务时，PI复核任务大小、技能和时间投入，确定更小的下一步。

### 调整后怎样确认有效
{: #guide-section-52 }

下次讨论检查上一轮决定和行动事项是否完成，以及阻碍是否解除。新增支持措施应有复核日期；无效时调整任务设计或指导方式。

## 9 讨论与导师反馈
{: #chapter_9 }

| **讨论类型** | **默认安排** | **材料与结果** |
| --- | --- | --- |
| 全组研究讨论 | 每周一次约90分钟，一名主汇报者 | 提前24小时共享图文材料，留出充分讨论时间 |
| 个人进度讨论 | 每两周25至30分钟；初期或遇到阻碍时追加短讨论 | 当前证据、待决定事项、下一步及双方行动事项 |
| 方法集中练习 | 新生或共性问题需要时安排，可替代当周部分组会 | 围绕代码或分析问题示范，再由学生操作 |
| 专题讨论 | 按需安排，只邀请相关人员 | 聚焦数据、方法或合作衔接，记录决定 |
| 培养回顾 | 每月简短能力复核，每半年完整发展讨论 | 复用研究材料，记录指导范围和训练目标 |

### 一次组会怎样进行
{: #guide-section-54 }

组会默认安排为：事务提醒5分钟；主要研究报告25分钟、讨论25分钟；文献或方法讨论25分钟；反馈与行动确认10分钟。可根据需要调整内容，不要求每周同时开展所有类型的讨论。

每名成员按排程定期深度汇报，轮换间隔根据成员人数确定。急需决定的项目提前安排讨论。尚未形成研究结果的新生，可汇报完整训练任务、复现差异或具体方法问题。

### 个别讨论的准备和会后工作
{: #guide-section-55 }

学生提前一天共享近期证据、上次行动完成情况和本次最需要决定的一至两个问题。PI优先处理关键选择和结果解释。会后由学生更新记录，导师确认双方的行动事项、日期和完成标准。

### 怎样使用导师时间
{: #guide-section-56 }

共性技术问题集中解决，个人研究范围和关键结论通过个别讨论确认。以15人每两周各讨论30分钟计算，个人讨论平均每周占用3.75小时；新生短反馈和材料阅读另计。PI应固定讨论时段，明确可提供即时反馈的安排。

PI暂时不能参加时，确定改期或替代讨论方式。学生记录阻碍，并推进可独立进行的任务；等待讨论期间沿用已有材料。

参考思路：Jo与Shen区分会议用途、SEM双方行动事项、Roberts提前准备议题。

## 10 研究记录与计算平台
{: #chapter_10 }

### 一项研究至少保留什么
{: #guide-section-58 }

研究材料须保留输入、版本、参数、日志与输出的对应关系。记录可用Markdown、文档或笔记系统，平台形式不作为能力评价依据。目录示例如下。

| **目录或文件** | **保存内容** | **主要要求** |
| --- | --- | --- |
| README.md | 项目概况、目录说明和材料入口 | 入口明确，随项目变化更新 |
| 00_docs/ | 研究计划、研究记录、讨论决定和方法说明 | 保留日期、已知限制及下一步 |
| 01_raw/ | 原始数据或受控位置链接 | 核对完整性、记录来源与时间、限制改写 |
| 02_metadata/ | 样本对应、来源、条件、批次与参考版本 | 编号一致，来源和权限清楚 |
| 03_qc/ | 质量检查结果、质控图和筛选记录 | 保留异常及处理依据 |
| 04_analysis/ | 代码、配置、参数、环境、日志与分析过程 | 版本可查，不保存账号凭据 |
| 05_results/ | 主要中间结果和最终结果 | 对应生成脚本及数据版本 |
| 06_figures/ | 结果图、底层数据和图注 | 可追溯、可重新生成 |
| 07_manuscript/ | 文稿、成果材料和交接说明 | 版本清楚，便于他人接续 |

根目录使用项目编号或Project命名，README.md说明文件位置；具体子目录按研究需要设置。

原始数据不得覆盖；正式分析代码必须保存；重要结果必须能够重新生成。

### 日常记录与文件命名
{: #guide-section-59 }

每天记录目的、步骤、结果位置、问题和下一步，保留成功命令、关键参数与重要失败。文件名建议包含项目、日期和内容，如P2026_001_20261011_sampleQC.tsv；用版本管理区分修改。

### 服务器和计算资源
{: #guide-section-60 }

遵守平台说明，通过作业调度提交资源需求较大的计算，不在共享登录节点运行重任务。提交前估计CPU、内存、时间、存储和GPU需求，用小数据试运行，并保存作业号与日志。按本平台实际调度方式维护操作说明，例如PBS；命令由联系人验证。

大任务明显超出已分配资源时，先与PI或平台联系人确认。异常作业应先检查日志和资源使用，避免反复提交相同失败任务。不得删除或覆盖他人文件。

### 备份与权限
{: #guide-section-61 }

项目启动时确认独立备份位置和负责人。关键材料形成或变更后及时备份；工作文件默认每周同步，原始大数据按平台策略处理。默认每季度抽查一次恢复。共享同一存储上的复制不等同于独立备份；受协议限制的数据按授权设置权限。

参考思路：Roberts研究记录、Rasi项目组织、Noble与Sandve计算研究记录。

## 11 分析质量与方法保障
{: #chapter_11 }

### 分析完成后必须检查
{: #guide-section-63 }

1．核对输入、样本身份、参考版本和分析单位，确认没有混用或漏项。

2．查看质量图、异常样本和日志；质量问题尚未解释时，不继续据此形成或扩展主要结论。

3．说明模型和统计假设，包括重复、对照、混杂、多重比较等与当前问题相关的条件。

4．核对图与底层数据、代码和参数；重要结论检查合理的替代设置或解释。

5．将关键结果、限制和需要复核的事项写入记录，再判断是否完成任务。

### 方法SOP怎样建立
{: #guide-section-64 }

SOP是可供执行和检查的标准操作说明。优先为重复使用、容易出错或多人共用的方法建立SOP，包含适用范围、输入、前提、步骤、质量检查、失败条件、排错、输出、命名、负责人和审核人。模板入口见附录A7。

SOP必须写明哪些设置依赖具体数据。任务负责人提出阈值及依据，由PI或合适的检查者确认。只有命令清单，缺少适用条件和检查办法的材料，不能视为已验证方法。

### 怎样发布与修改
{: #guide-section-65 }

方法作者先用小数据验证，保存测试数据或获取方式；另一成员按说明执行，记录不清楚或不一致之处。PI或指定检查者确认适用范围后，标为可用。软件或关键步骤改变时，更新版本和变更说明，并保留原有分析使用的版本。

### 怎样复核重要结果
{: #guide-section-66 }

成员先自查，再对支撑主要结论的图表或关键步骤进行独立检查。小规模计算可以重跑；昂贵计算先核对输入、参数、日志和中间结果，再安排必要的重建。复核记录写明检查范围、发现的差异和处理情况。

### 错误发现后怎样做
{: #guide-section-67 }

发现错误后保留原材料，标记受影响结果，评估对结论和后续工作的影响，并与PI讨论修正办法、记录处理过程。已共享或进入投稿材料的错误应及时通知相关作者，必要时按期刊或学校要求处理。主动报告错误是研究责任的一部分。

参考思路：Poldrack分析程序、SEM代码与图检查、Sandve可重建结果。

## 12 研究诚信 合作与AI辅助
{: #chapter_12 }

### 研究记录和结论
{: #guide-section-69 }

不得编造数据、伪造记录、隐瞒影响结论的质量问题，或篡改图中的科学信息。保留排除样本、选择参数和调整分析的理由。探索中形成的想法，应在后续验证中说明来源，不把事后选择写成预先确定的设计。

### 合作与贡献
{: #guide-section-70 }

项目开始时讨论预期分工、数据使用和贡献记录，作者资格及次序根据实际贡献确认。定期更新贡献记录，在重要分工变化、写作前和投稿前讨论作者资格与排序。所有作者都有机会检查与自己相关的材料及最终稿。

使用合作方未公开数据、代码或成果时先确认授权范围。共享、投稿和公开数据需遵守约定；不得自行扩大使用或公开。合理分歧先基于贡献与记录讨论，需要时请合适第三方或学校渠道协助。

### AI可以怎样帮助科研
{: #guide-section-71 }

AI可用于理解概念、草拟代码、排错、整理资料和修改表达。使用者仍须理解、核对并承担责任，核实引用、方法和结果。AI生成内容不能替代本人对研究的理解。

1．核实引用和关键事实；确认函数、参数、依赖与数据假设实际存在。

2．生成代码先在小数据上验证，检查边界情况和关键输出，保留本人修订。

3．影响关键分析或判断的AI协助，应记录工具、时间、任务、必要提示词和检查证据。

4．未获允许，不向外部工具上传未公开数据、合作资料、个人敏感信息或账号凭据。

5．论文、申请书和正式评审材料的使用与披露要求，按相关机构、期刊及合作约定确认。

### 交付前必须能解释
{: #guide-section-72 }

交付前，学生应能说明结果如何产生、为什么采用该方法，以及做过哪些检查。无法解释关键代码或结论时，先继续理解与核验。使用AI辅助工具与开展AI模型研究是不同任务，不能以工具使用替代模型研究所需的方法理解与验证。

参考思路：Shen与Poldrack AI政策、Coaker与Jo贡献讨论。

## 13 湿实验与计算分析衔接
{: #chapter_13 }

### 先确认实验服务于哪个判断
{: #guide-section-74 }

湿实验开展较少，也应在开始前明确要检验的问题、现有计算证据的限制，以及什么结果能够支持或削弱当前解释。先与平台或合作者确认技术、样本和资源，再决定规模；新技术优先开展小规模试验。

### 实验开始前的准备
{: #guide-section-75 }

1．列出实验问题、样本、对照、独立重复、主要观察和判定办法，与PI共同确认。

2．按学校和平台要求完成培训与权限确认，在已经获准的范围操作；没有掌握的方法先由合适人员示范。

3．确认样本编号、取样与处理记录、保存方式、质量要求和后续数据输出。

4．与合作者明确各自负责的步骤、交付内容、失败处理和贡献记录。

### 样本信息怎样进入计算分析
{: #guide-section-76 }

同一编号应贯穿材料、实验、测序或检测、原始文件和分析结果。至少记录物种与材料身份、组织、时期、处理、重复、实验或检测批次、所用方法版本和必要质量信息。倍性等与分析有关的信息一并确认。

接收数据时核对样本表、文件对应关系、完整性和质量记录。需要平台补充的信息应明确列出，不猜测或补造。样本标签存在冲突时，先暂停受影响分析，联系提供者核对。

### 怎样保存实验过程
{: #guide-section-77 }

记录日期、操作者、真实操作、关键变化、原始检测或观察结果和异常。计算解释所用的实验记录应能定位。图片调整应保留原始材料，并遵守相应研究与发表要求。

### 进入下一步前的检查
{: #guide-section-78 }

先判断实验是否达到约定质量，再解释生物学结果。失败时区分方法、样本、记录与假设问题，讨论是否重做、改变设计或停止。验证计算结论时，应明确实验支持的结论范围。

本章规定设计、记录与衔接责任。具体实验按已经验证的SOP和平台要求执行，不能直接使用未经核对的网络或AI操作建议。

## 14 论文成果与毕业
{: #chapter_14 }

### 研究过程中同步整理成果
{: #guide-section-80 }

每形成一项重要结果，及时保存图、图注、底层数据、生成脚本和对应方法说明。定期检查研究问题与现有证据的关系，先明确主要结论和限制，再组织稿件。图序和段落应说明证据如何回答问题。

### 进入写作和投稿
{: #guide-section-81 }

1．负责人提出核心问题、主要结论、证据顺序与仍缺的关键分析，PI共同确认范围。

2．逐图核对样本、分析单位、统计、数据和脚本；重点结果安排适当的独立检查。

3．整合方法、材料、版本、数据和代码获取说明，核对引用与结论范围。

4．讨论实际贡献、作者资格和排序，合作者检查相关材料，全体作者确认最终稿。

5．核对目标期刊当时的数据、代码、AI披露与其他要求；完成需要的授权和公开准备。

### 软件 数据与方法成果
{: #guide-section-82 }

可以形成可用的脚本、流程、数据资源或方法手册。交付应包括用途、适用范围、输入输出、安装或环境、示例、质量检查、已知限制和维护人。成果形式由研究内容决定，不要求所有成员都建立大型软件项目。

### 毕业或离组交接
{: #guide-section-83 }

默认在拟离组前至少4周开始准备，学位节点按学校安排落实。使用附录A8列出项目状态、结果与数据位置、代码环境、方法、未完成任务、合作与贡献、权限及后续联系人。大型项目提前安排。

接收者应实际定位文件，并重建一个关键小结果，记录失败及处理。原始数据和关键记录不能仅保存在个人电脑、私人云盘或即将失效的账号中。访问权限调整由PI与相关管理者确认，并保留合法授权范围。

### 离组后的工作
{: #guide-section-84 }

离组时书面确认未完成论文、数据请求、后续贡献和联系安排。新增任务与合作另行商定，交接不默认产生无限期免费工作的义务。

参考思路：Coaker投稿材料、SEM结果检查、Roberts与Rasi可接续研究记录。

## 15 实施与持续修订
{: #chapter_15 }

### 先建立清楚的入口
{: #guide-section-86 }

初期建立一个指南入口、一份人员培养记录、一份项目概览及各项目的研究文件位置。可使用已有共享文档、内部存储和代码管理工具；迁移时保留编号与链接。联系人和资源列表由PI确认。

| **时间** | **应完成的事情** | **怎样检查** |
| --- | --- | --- |
| 启动第1周 | 讨论共同规则；确认时段与联系人；列出成员和项目 | 每人知道任务、记录位置和求助方式 |
| 第2周 | 补齐项目首页；启动讨论排程；导师示范图文报告 | 检查问题、下一步、完成标准和待决定事项是否明确 |
| 第3至6周 | 新生完成训练任务；启动能力回顾；抽查关键分析 | 检查能否解释结果，困难是否更早提出 |
| 第6周回顾 | 收集意见；删减重复要求；调整讨论和任务大小 | 判断安排是否帮助学习和决策 |
| 每季度 | 复核项目与规则；抽查记录及备份恢复；调整指导 | 记录修改内容、原因及生效时间 |
| 每学期 | 回顾培养目标；整理方法说明与轮值安排 | 检查能力进步与学位计划，维护联系人 |

### 把教育支持和责任处理分开
{: #guide-section-87 }

初次未达到要求时，先了解原因，提供示范或缩小任务。连续未按约定执行时，明确事实、责任和两周改进计划；仍无改善时按学校规定处理。发现数据诚信或公共资源问题，应及时控制受影响工作并保存事实。

### 哪些现象值得观察
{: #guide-section-88 }

观察学生是否更能解释问题与方法，是否更早提出困难，下一步和导师决定是否可查，重要结果是否可重建，以及材料准备是否重复。这些信息用于改进安排，不合成为个人排名分数。

### 怎样修改指南
{: #guide-section-89 }

每次修改记录章节、原因、影响和生效时间，由PI确认并向成员说明。调整培养安排和共同科研时段前听取成员意见；因平台规定或项目协议变化而调整时，说明依据。默认每季度小修、每学年系统回顾。

不能帮助理解研究或作出决定的记录要求，应删减或合并。共同规则保留在指南中，技术细节纳入可持续更新的SOP。
